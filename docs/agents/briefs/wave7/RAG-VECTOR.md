# Wave 7 task: knowledge bases that actually retrieve (RAG, embeddings, hybrid search)

Rules: docs/agents/briefs/wave1/BUILD.md. Branch: wave7/rag-vector from the local branch wave2/integration (head 04c7312 or later; it already has documents, memory-retrieval, the `Retriever` abstraction and rerankers in src/retrieval.ts from wave 6, local-models with an embeddings call for Ollama, and a `data.*` family). Themes: documents-and-rag (#57, 41 pieces) and vector-and-hybrid-memory (#75, 19 pieces). Backend first; small additive UI in the existing Documents section only. No new dependency: embeddings come from the providers the owner already connected (OpenAI `/embeddings`, Gemini embedContent, Ollama `/api/embeddings`, LM Studio), vectors live in SQLite as float32 blobs with cosine similarity computed in TypeScript, and a pure-TS BM25 sits beside the existing FTS.

Read first: src/documents.ts, src/retrieval.ts, src/memory-retrieval.ts, src/local-models.ts (embeddings), src/providers.ts, src/store.ts (schema/migrations pattern), src/data-tools.ts, docs/CHECKPOINT.md sections on documents and retrieval, tests/documents.test.mjs, tests/sdk-misc.test.mjs (reranker tests).

Build:
1. Embeddings service (`src/embeddings.ts`): one `Embeddings` interface (`embed(texts) -> Float32Array[]`, `dimensions`, `model`, `local: boolean`) with adapters for OpenAI-compatible, Gemini and Ollama/LM Studio, chosen by the owner's model plan ("prefer a model on this computer" honoured); batching, retries through the existing provider retry helper, cost recorded through the usage ledger like any model call, and a plain refusal when no connection can embed. Cache by sha256(text+model) in a table so re-indexing is free.
2. Vector store (`src/vector-store.ts`): SQLite table `vectors(collection, doc_id, chunk_id, model, dims, blob, text_hash)`, cosine top-k in TS over a collection (fine up to ~50k chunks; say so in docs), with a pluggable `VectorBackend` interface so a future adapter (Qdrant/Chroma over HTTP) can slot in. Implement the interface and the SQLite backend only; write the HTTP adapter contract in docs, not code.
3. Chunking and parsing (`src/chunking.ts`): heading-aware Markdown chunking, paragraph windows with overlap for plain text, PDF/DOCX through the existing document readers (do not add parsers), per-chunk metadata (title, heading path, page), deterministic chunk ids.
4. Knowledge bases (collections): `knowledge.create/list/add/remove/reindex/search` tools + routes; a collection is a named set of workspace folders or documents; indexing runs as a background job with progress events; hybrid search = BM25 (pure TS over the chunk table, with the existing FTS as first-stage candidate filter) fused with vector scores (reciprocal rank fusion), then the wave-6 reranker; results carry citations (document, heading, page). Wire it behind the wave-6 `Retriever` interface so `documents.search` and run-time context injection use it when a collection is attached to the conversation or project.
5. Vector-backed long-term memory: memory facts get an embedding on write (through the cache) and `memory.search` becomes hybrid (existing word search + vector) with the same fusion; a nightly "consolidate" pass (existing scheduler tick) merges near-duplicate facts by similarity above a threshold, proposing, never deleting on its own (matches the wave-3 hygiene rule).
6. Agentic retrieval: a `knowledge.ask` tool that lets the model pick a collection, search, read the top chunks and answer with citations; plus a "Knowledge" card in Documents listing collections, their size, last index time, embedding model and a Reindex button.
7. Docs: docs/configuration.md "Knowledge bases" in plain language (what gets sent to which provider when indexing, that local models keep it on the computer, how much it costs, limits).

Tests (tests/rag-vector.test.mjs, all with fake HTTP endpoints, no real provider calls): embeddings adapters parse each provider's shape and cache hits skip the network; cosine top-k correctness on a tiny hand-computed set; chunker respects headings/overlap and is deterministic; BM25 ranks an exact rare-word match above a common-word match; fusion puts a document strong in both above one strong in one; a collection indexes a temp folder, search returns the right chunk with a citation, reindex after edit updates it; memory hybrid search finds a paraphrase the word search misses (fake embeddings that make the paraphrase close); consolidation proposes a merge and deletes nothing; `knowledge.ask` cites. Existing documents/memory/sdk-misc tests stay green.
