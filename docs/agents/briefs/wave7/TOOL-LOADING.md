Build:
1. Three tiers per tool, decided each round: `loaded` (full dieted schema in the request), `indexed` (one line: name + eight-word purpose, in a compact index block, at most N lines, default 40), `deferred` (not in the request at all; findable only through `tools.search`). Core tools are always loaded; tools used in the last K rounds stay loaded; everything else is indexed or deferred by score. Hard token budget for the whole tool section per round (default 2,500 estimated tokens, config `toolBudgetTokens`), enforced by demoting the lowest-scored loaded tools first, then trimming the index; the `ContextBudget` event reports loaded/indexed/deferred counts and tokens. With 1,000 registered tools the request must stay under the budget.
2. `tools.search {query, limit?}` (core, always loaded): hybrid search over every registered tool the run is permitted to use (BM25 over name + description + parameter names + group + learned notes, fused with embeddings when the embeddings service is available and the owner allows it; cache tool embeddings by sha256 of the description), returning matches with their purpose and a one-line usage hint; matched tools become `loaded` for the rest of the conversation (respecting the budget). Also `tools.describe {names}` to load specific tools by exact name. Both are permission-gated exactly like `tools.expand`: a narrowed run can never find a tool it is not allowed to use. Keep `tools.expand` working (groups become a convenience over the same index).
3. Learning, safely (the "better than Hermes" part): a `tool_usage` table records, per owner, for each run: the prompt's word set (hashed shingles, not raw text), the tools searched for, the tools called, success/failure, and round count. From it: (a) pre-loading: before round 1, score tools by similarity of the new prompt to past prompts that led to each tool (plus the existing lexical table), so repeated kinds of requests need no search; (b) co-use: tools that are usually called together load together; (c) demotion: tools never used in 30 days drop to deferred; (d) `tool notes`: when a tool call fails with a schema error and the retry succeeds, or when the model explicitly says a tool needed something ("remember: X needs the full path"), a short note is stored and appended to that tool's indexed line and description (owner-visible and deletable). All of this is data on this computer; nothing leaves; export/import with the backup. Show the effect: the `catalog.size` event includes `preloadedFromHistory: [...]`.
4. External tools at scale: MCP servers with hundreds of tools, plugins and skill packages register into the same index without being loaded; a server's tools are searchable the moment it connects; `notifications/tools/list_changed` re-indexes. Descriptions from external servers are treated as untrusted text: run them through the injection detector and cap their length before they can appear in any request.
5. Self-check and reporting: a nightly (existing scheduler tick) "catalog health" pass computes per-tool use counts, search hit rates, average tokens per round, and writes a short plain-language line to the diagnostics bundle; the Developer card shows: loaded now, indexed now, deferred count, budget used, top pre-loads and why ("you asked for a chart three times this week").
6. Docs: docs/configuration.md "How the assistant finds its tools" in plain language (why it sometimes "looks for a tool", that it remembers what worked, how to delete that memory, the budget setting), and a note in docs/design.md for the Developer card.

Tests (tests/tool-loading.test.mjs, fakes only): 1,000 dummy tools + 20 scripted rounds stay under the budget and every request is smaller than the same run with only groups; a tool that is deferred is found by `tools.search`, loaded, called, and stays loaded; a narrowed run cannot find a forbidden tool by search or describe; `tools.search` ranks an exact-name and a synonym query correctly (table of at least 12 queries, including "make a picture", "what's on my screen", "pull the Ollama model", "open my calendar", "read that PDF", "check Discord"); learning: after two runs where "chart the sales CSV" led to data.chart, a third run pre-loads it with no search; co-use loads the pair; a 30-day-old unused tool is deferred; a tool note is recorded from a failed-then-fixed call and appears in the description; MCP server with 300 tools connects, is searchable in the same round, and its descriptions are length-capped and injection-filtered; export/import round trip; the health pass writes its line.
