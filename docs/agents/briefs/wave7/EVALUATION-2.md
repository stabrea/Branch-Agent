Build:
1. Evaluation framework (A0884, A1128, A1009, A0927, A1010): `Evaluator` interface (`score(task, trajectory, answer) -> {score, pass, reasons}`) with built-in scorers: exact match, contains, regex, JSON-schema validity, numeric tolerance, file-exists/file-contains in the workspace, "tool was called with", trajectory length/cost/latency budgets, and a model-graded rubric scorer (one call, cached, off unless a connection is chosen); `EvaluationRun` records per task: trajectory id, scores, cost, duration; gates (A1010): thresholds that mark a run failed and can block a release script (`branch eval --gate`); results persisted with history (extend the wave-4 tables, do not duplicate).
2. Benchmark adapters (A1691, A0570, A0926, A1231, A0499): a `BenchmarkAdapter` interface (`discover(dir) -> tasks`, `prepare(task) -> workspace`, `judge(task, result)`) and adapters that read the public formats from LOCAL files: SWE-bench Lite/Verified instances (JSONL with repo, base_commit, problem_statement, test_patch; prepare = clone/checkout only if the repo is already on disk in a configured folder; judge = run the named tests through the shell with the job limits) (A0297/A0460/A0571/A0724/A0347); GAIA (metadata JSONL + attached files; judge = normalised exact match) (A1550/A1728); APPS/MBPP/HumanEval-style code tasks (JSONL with prompt + tests; judge = run tests) (A0499); WebVoyager/BrowserGym-style web tasks converted to local fixture pages where possible, else documented as requiring their environments (A1714/A1726); terminal-bench style tasks (a folder with task.md + tests.sh) (A0725); OSWorld/WindowsAgentArena/AndroidWorld documented as NOT integrated (they need VMs) (A1593/A1598/A1599/A1727/A1692). Each adapter ships with a tiny synthetic sample in tests/fixtures so the pipeline is proven without the real datasets.
3. Experiments (A1722 study abstraction, A1723 parallel loop, A1729 inspection, A1594 Best-of-N, A1252/A1253 AGBench-style runner and tabulation): a `study.json` describes benchmark, subset, model/profile matrix, repeats, budget caps; `branch study run` executes tasks in parallel under the existing concurrency limit with retries and per-task checkpoints (resume after a crash), writes results as JSONL + a Markdown table; Best-of-N: run N trajectories and pick by a scorer or a judge; `branch study compare a b` tabulates deltas with confidence (bootstrap over tasks, no library); the Evaluation screen lists studies and shows the table.
4. Deterministic testing utilities (A0973): export a `ScriptedProvider` and `ScriptedTools` from the package (`packages/sdk` or `src/testing.ts`) so plugin authors and contributors can write deterministic tests; document them.
5. Tool evaluations (A0078) and task completion review (A0375): per-tool eval suites (input → expected result shape) runnable in CI; a "did it actually finish?" reviewer scorer using the existing completion checks.
6. Telemetry for evals (A0248, A1190): every eval task is a trace (wave 7 tracing) tagged with study/benchmark ids so exports carry them; trajectory scoring reads spans.
7. Docs: docs/configuration.md "Measuring the assistant" in plain language: what a suite, a benchmark and a study are, where to put dataset files, what is NOT supported and why, cost warnings; README bullet.
