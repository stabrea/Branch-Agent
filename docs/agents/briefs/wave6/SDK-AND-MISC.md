# Wave 6 task: SDK, issue trackers, audit records and the "other" list

Rules: docs/agents/briefs/wave1/BUILD.md. Branch: wave6/sdk-misc from the local branch wave2/integration. Theme: other (#60) plus leftovers: A0308 TypeScript SDK, A0174/A0395 issue-tracker context (GitHub issues, Linear), A0591 runtime audit records, A0434 per-tool approval categories, A0326 onboarding sandbox, A0370 interactive specification elicitation, A0575 pluggable LLM drivers, A0817/A0995 retriever abstraction and reranking, A0300 pull-request hook. Backend first; tiny additive UI only.

Read: src/server.ts routes, src/openai-compat.ts, src/streams.ts, src/ws.ts, src/integrations/github.ts (wave 2), src/policy.ts, src/activity.ts, src/receipts*.ts, src/plugins.ts (wave 4, if merged; otherwise the wave4/skills-plugins branch), src/documents.ts and src/memory-retrieval.ts, docs/configuration.md.

Build:
1. TypeScript SDK (A0308): `packages/sdk/` inside the repo (no publish step), a dependency-free client for the local API: runs (start, stream events over SSE/WebSocket, steer, cancel, resume), sessions, memory, documents, schedules, policy approvals, with typed inputs generated from the zod schemas where possible (a small generator script) and a README with three examples. Tests run the SDK against a real `startServer`.
2. Issue-tracker context (A0174/A0395): `issues.search/get/comment` for GitHub (extend the existing GitHub tools) and Linear (GraphQL, token in the locker), plus "context from an issue link": pasting an issue URL in the composer pulls title/body/comments into the run as a document-style passage with a citation; the open-pull-request hook (A0300) gains a template that links the issue.
3. Audit records (A0591): a dedicated append-only `audit` table (who/what/when/why, source, run id, outcome) written for approvals, secret use, policy changes, channel pairing, exports and profile switches; `GET /api/audit` with filters and CSV export; included in the diagnostics bundle; a plain-language "What the assistant was allowed to do" screen section under Usage.
4. Per-tool approval categories (A0434): group tools into categories (read, write files, run commands, browse, message people, spend money, change settings) shown in the approval settings so the owner can set a decision per category instead of per tool; categories derived from permissions with a small override map.
5. Ask-before-starting (A0370): a run option (and a rail toggle) "Ask me questions first" where the model must produce up to five clarifying questions with suggested answers before doing work; answers are appended to the prompt; skipped automatically for short, unambiguous prompts by the same heuristic used for auto-plan.
6. Onboarding sandbox (A0326): first run offers a "practice workspace" with sample files and a demo conversation so a new person can try tools safely before pointing the app at their real folders; one click switches to a real workspace.
7. Retrieval abstraction and reranking (A0817/A0995): a `Retriever` interface with the existing FTS, hybrid and memory retrievers behind it, plus a reranker step: cheap lexical rerank by default and an optional model-based rerank (one call, top 20 → top 5) when the owner enables it; used by documents and memory retrieval.
8. Pluggable LLM drivers (A0575): a provider plugin type in the plugins loader (`plugin.provider.<id>`) so a plugin can register a new provider adapter implementing the Provider interface; documented with a tiny example plugin in the tests.

Tests (tests/sdk-misc.test.mjs and packages/sdk/test): SDK round trips; issue context from a fake GitHub/Linear server with token redaction; audit rows for approval and secret use, CSV export; category decisions expand to rules; ask-first produces questions and skips for a short prompt; practice workspace creation and switch; reranker changes order deterministically and model rerank is called once; provider plugin registers and completes with a fake endpoint.

Acceptance: O1 SDK proven against a live server; O2 issue context proven; O3 audit proven; O4 categories proven; O5 ask-first proven; O6 sandbox proven; O7 reranker proven; O8 provider plugin proven; O9 docs; O10 no new dependency. Report the ids you consider done.
