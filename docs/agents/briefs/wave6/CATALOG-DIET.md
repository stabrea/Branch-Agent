# Wave 6 task: keep the tool catalog small and the context healthy

Rules: docs/agents/briefs/wave1/BUILD.md. Branch: wave6/catalog-diet from the local branch wave2/integration. Themes: context-management (#82) and reliability (inventory #16). Backend only. This is a load-bearing task: the app now has roughly 90 tools and every model round pays for the whole catalog (about 9–10k estimated tokens), which already forced two builders to raise `compactionThreshold`; two more waves of tools are coming.

Read: src/registry.ts (descriptions, permissions, schema generation), src/runtime.ts (loop, fitContext, compaction, `compactionThreshold`, `contextLimit`), src/reliability.ts, src/contracts.ts (ToolDefinition), tests/compaction-attention.test.mjs, tests/reliability.test.mjs, docs/CHECKPOINT.md notes on budgets.

Build:
1. Tool groups with lazy expansion: every tool gets a `group` (files, code, git, web, browser, desktop, memory, documents, data, research, media, channels, schedules, agents, skills, settings, ...). Each round the model sees the core tools plus a compact list of collapsed groups ("browser: 12 tools — call `tools.expand {group}` to see them"); expanding a group adds its tools for the rest of the conversation. Tools used in the last N rounds stay expanded. Measure and log the catalog size per round (`catalog.size` event) so the effect is visible.
2. Relevance pre-selection: a cheap lexical scorer (prompt words, recent messages, active project, recent tool use) pre-expands the two or three most likely groups before the first round so simple tasks never need an extra round; tests with a table of prompts → expected groups.
3. Schema diet: shorten generated JSON schemas (drop `$schema`, `additionalProperties:false` where the registry already enforces strictness, `title`s, redundant descriptions; keep enum values and required lists), cap description length, and de-duplicate boilerplate; measure before/after in a test (target: at least 35 percent smaller catalog at the same tool count).
4. Context accounting made explicit: one `ContextBudget` object per round (limit, system, catalog, messages, reserve for the answer) with a `context.budget` event; compaction triggers on the messages share only, never because the catalog grew; `compactionThreshold` becomes derived (limit − catalog − reserve) instead of a constant, with the old constant kept as a floor for tests that reference it (export both).
5. Provider-native compaction hints: when the provider supports prompt caching (Anthropic `cache_control`, OpenAI automatic prefix caching), order the request so the system prompt and catalog come first and are stable across rounds; add the cache markers for Anthropic; measure reported cached tokens in usage when the provider returns them.
6. Guardrails: a test that registers 150 dummy tools and proves a 20-round scripted conversation neither thrashes compaction nor exceeds the limit; a test that the model can still discover and call a collapsed tool through `tools.expand`.

Tests (tests/catalog-diet.test.mjs): groups and lazy expansion; relevance table; schema diet size assertion; ContextBudget event values; derived threshold; Anthropic cache markers present and ordering stable; the 150-tool guardrail; all existing reliability/compaction/runtime tests green (update `compaction-attention` only if its literal no longer applies, and say so).

Acceptance: CD1 catalog per round at least 35 percent smaller with all groups collapsed and the same tool count (numbers in the report); CD2 collapsed tools still callable; CD3 derived threshold; CD4 cache ordering/markers; CD5 150-tool guardrail; CD6 docs/configuration.md section in plain language ("why the assistant sometimes says it is opening a toolbox"); CD7 no new dependency.
