Build:
1. Network policy for WebSockets: `policy.connect(url, headers)` that applies the same allowlist/private-address/credential rules as `assertAllowed`, returns a guarded `WebSocket` (Node 24 global), records a span and an audit line per connection, caps concurrent outbound sockets, and closes them on run end, Lock and app close. Tests against a local fake WebSocket server: allowed host connects, disallowed refused before any bytes, private address refused unless the switch is on, token never logged.
2. Realtime sessions: a `RealtimeSession` interface (open, sendAudio(pcm16 chunks), sendText, onTranscript, onAudio, onToolCall, interrupt, close) with two adapters: OpenAI Realtime (WebSocket, session.update with the owner's voice/instructions, input_audio_buffer.append/commit, response.create, server VAD on/off setting, function calling mapped to the tool loop through the existing runtime with the same approval gate and toolboxes) and Gemini Live (BidiGenerateContent WebSocket, same mapping). Capabilities come from the provider catalog (`realtime: true` on the entries that offer it); a connection that lacks it gets the plain sentence and talk mode falls back to the wave-7 pipeline.
3. Talk mode, live: the composer's Talk button gets a "live" variant when a realtime-capable connection is selected: microphone audio streams up (browser AudioWorklet → PCM16 over the existing run WebSocket → the session), the answer plays as it arrives, pressing again interrupts (cancel the response and clear the buffer), the transcript of both sides lands in the conversation as ordinary messages, tool calls the model makes mid-conversation show as the normal tool rows, and cost is recorded from the session's usage events. "Keep audio on this computer" refuses live mode entirely with the reason.
4. Bidirectional text streaming (A1193): the same session interface accepts typed text mid-conversation and streams tokens back over the run WebSocket, so a person can type while the assistant is speaking; documented as the same feature.
5. Safety: the session's instructions include the owner's standing rules; a realtime tool call cannot bypass approval (prove with a tool that needs a yes: the model hears "waiting for your yes" and the card appears); no audio is stored unless the owner turns on recordings; a session is capped by minutes and dollars from the existing budget settings and closes with a spoken sentence when it hits the cap.
6. Docs: docs/configuration.md "Live conversation" in plain language (what is sent, cost per minute, how to interrupt, why it needs a realtime-capable connection, what "keep audio on this computer" does).
