# Wave 5 task: installing, starting and reaching the app from anywhere

Rules: docs/agents/briefs/wave1/BUILD.md. Branch: wave5/deployment from the local branch wave2/integration. Themes: deployment-and-packaging (#73), mobile-and-remote-access (#87), operations inventory items (#14: onboarding, daemon, portable builds, migration). Desktop code IS in scope for this task (src/desktop/*, scripts/package-desktop.mjs), but never run tests/desktop*.test.mjs yourself; write the tests and I will run them.

Read: src/desktop/main.ts, src/desktop/updater*.ts, src/desktop/hand-over.ts, scripts/package-desktop.mjs, scripts/prepare-icon.cjs, src/server.ts (bind address, Host check, token), src/cli.ts, docs/CHECKPOINT.md updater incident notes, tests/updater*.test.mjs.

Build:
1. Installer without signing: a self-extracting installer built by the package script with only Node built-ins and Windows tools already present (a `.cmd`/PowerShell bootstrapper next to the zip is acceptable): installs to `%LOCALAPPDATA%\Programs\Branch Agent`, creates Start menu and optional desktop shortcuts (WScript.Shell), registers "Uninstall" in Add/Remove Programs (HKCU Uninstall key with a quiet uninstall script), keeps `.previous`, and migrates data from an older folder layout if found. Portable mode: a `portable.txt` beside the exe makes the app keep its data next to itself.
2. Start with Windows (opt-in switch in Settings) via a HKCU Run entry or a Startup-folder shortcut; "Start minimized to tray".
3. Background service mode: `branch daemon install|uninstall|status` registers a Task Scheduler task that starts the server headless at logon (no window), so schedules, channels and triggers keep working when the app window is closed; the desktop app attaches to a running daemon instead of starting a second server (detect by the port + token file; single instance stays).
4. Remote access, safely: an opt-in "Reach Branch from my phone" that binds the server to the Tailscale interface only when Tailscale is present (detect `tailscale status --json`), shows a QR code (pure-JS QR encoder, no dependency) with a one-time pairing link, requires the pairing code on the phone, and keeps the Host/Origin checks (extend the allowlist to the Tailscale hostname/IP). Never bind to 0.0.0.0. Mobile layout already exists; verify the pairing page works at 400 px.
5. Migration and backup on update: the updater takes a backup (existing backup route) before swapping files, keeps the last three, and offers "restore the previous version's data" in the update screen if the new version fails its health check on first start.
6. Setup flow: `branch doctor --fix` for common problems (missing Playwright browser, no git, blocked port) with plain-language steps; first-run checklist in the app already exists — extend it with "start with Windows" and "reach from my phone" toggles.

Tests (tests/deployment.test.mjs, no Electron): installer script generation and a dry-run into a temp folder that creates the folder layout, shortcuts (verify .lnk files exist) and the uninstall registry key under a test hive path parameter; portable mode data location; daemon task command construction (do not actually register a task in tests; use the existing hand-over launch abstraction with a fake exec); QR encoder produces a valid matrix for a sample URL (verify finder patterns); pairing flow route tests; backup-before-update logic with a fake updater; doctor --fix report.

Acceptance: P1 installer dry run proven; P2 start-with-Windows and daemon commands proven with fakes; P3 remote access binds only to Tailscale and needs pairing (tests); P4 backup before update proven; P5 docs (README install section rewritten in plain language, docs/configuration.md); P6 no new dependency.
